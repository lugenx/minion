User feedback:
1. "isnt 5 seconds too long?"
2. "what else needs to be humanized?"

Analysis:
1. **Delay length:** 5 seconds *is* quite long for an automated process, especially if the user puts 10 queries in a file (that's nearly a minute of just waiting). A delay of 1 to 3 seconds is usually sufficient to bypass simple anti-bot rate limits without feeling unbearably slow.
2. **What else needs humanizing?**
   - **User-Agent:** We are already sending a standard Chrome User-Agent header, which is good. But it's hardcoded.
   - **Delay between Scrape requests:** Currently, after the search is done, the engine immediately iterates through `allURLs` and fires HTTP GET requests to scrape the targeted websites as fast as the CPU can process the loop. If a single YAML file points to 10 different pages on the *same domain* (e.g., via `follow_links`), hammering that domain with 10 requests in 0.5 seconds will instantly trigger their WAF (like Cloudflare or Akamai) and get the IP banned.
   - We need a small, random jitter (e.g., 1 to 2 seconds) inside the main `allURLs` scraping loop as well, to ensure we don't accidentally DDoS the target websites.
